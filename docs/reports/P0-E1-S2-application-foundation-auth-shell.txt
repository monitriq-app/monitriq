10. TYPOGRAPHY / VISUAL-TOKEN IMPLEMENTATION
-----------------------------------------------
IBM Plex Sans loaded via `next/font/google` (self-hosted, no external
runtime request), exposed as CSS variable `--font-ibm-plex-sans` on <html>.
A `tabular-figures` Tailwind v4 custom utility (`@utility` directive) sets
`font-variant-numeric: tabular-nums lining-nums` for future financial
figures.

Two-layer token architecture, per the phase's explicit split requirement:
- BRAND tokens: imported directly from the canonical
  docs/reference/brand/brand-tokens.css via `@import` in app/globals.css —
  never redefined or copied by hand, so there is exactly one source of
  truth and no drift risk.
- SEMANTIC UI tokens: lib/styles/tokens.css maps brand tokens onto
  background, surface, surface-raised, surface-muted, border, text-primary,
  text-secondary, text-muted, accent-primary, positive, attention, danger,
  and focus via Tailwind v4's `@theme`, so components use classes like
  `bg-surface` or `text-danger`, never raw hex values.
Dark-first: three brand darks (Obsidian, Ink, Midnight Navy) are layered as
background/surface/surface-raised; surface-muted and border are derived via
CSS `color-mix()` rather than inventing new unlisted hex values. Token
names are semantic, not dark-specific, so a future `[data-theme="light"]`
override block can redefine the same custom properties later without
touching component code — no light mode was built this phase, per
instruction.

11. SUPABASE ARCHITECTURE
----------------------------
- lib/supabase/client.ts — browser client (createBrowserClient), for
  Client Components only.
- lib/supabase/server.ts — server client (createServerClient, cookies-
  based) for Server Components/Route Handlers.
- lib/supabase/session.ts — updateSession() helper that refreshes the auth
  cookie on every request; used by proxy.ts (Next.js 16 renamed the
  `middleware.ts` file convention to `proxy.ts` — this was applied; see
  section 17).
- lib/supabase/get-current-user.ts — getCurrentUser(), wrapped in React's
  `cache()` so a layout's auth check and a page below it don't duplicate
  the Supabase Auth round trip within one request.
Both browser and server clients use only the public URL + anon key. No
service-role client exists anywhere in the codebase.

12. AUTHENTICATION ARCHITECTURE
-----------------------------------
Routes: /login, /signup, /forgot-password, /update-password (all under
app/(auth)/, sharing a minimal branded layout), and /auth/callback (Route
Handler that exchanges a one-time code for a session — lands both email-
verification links and password-recovery links).
Flows wired: sign up (supabase.auth.signUp, email-redirect to
/auth/callback), sign in (signInWithPassword), sign out (SignOutButton
client component), password recovery (resetPasswordForEmail →
/auth/callback?next=/update-password → updateUser). Session refresh via
proxy.ts on every request. No social providers implemented (none required
this phase). No fake/mock authentication — every flow calls real Supabase
Auth APIs; they are implemented but unverified end-to-end since no live
Supabase project is connected (see section 18, risks).

Issue found and fixed during this phase's own validation (documented per
instruction to not describe the phase as complete without fixing or
flagging): an initial version of app/(app)/layout.tsx gated on Supabase
configuration by returning `<ConfigurationNotice />` instead of `{children}`
when unconfigured. `next build` and `tsc`/`eslint` all passed against this
version — the defect was invisible to every mandatory validation check.
It was only caught by additionally running `next dev` and inspecting the
server log, which showed `/home` throwing an uncaught "Missing required
environment variable" error even though the HTTP response was a correct
200 showing the configuration notice. Root cause: Next.js can render a
layout and the page segment nested inside it concurrently for performance,
so a layout that omits `{children}` from its return value does not
reliably stop the nested page's Server Component from executing — only
`redirect()`/`notFound()` (which throw a router-level signal) reliably
short-circuit this. Fix: `getCurrentUser()` now returns `null` instead of
throwing when Supabase isn't configured (treating "not configured" the
same as "not signed in"), `app/(app)/layout.tsx` now uses a plain
`redirect("/login")`, and the "Not configured" state moved to the public
landing page (a leaf component with no nested child segment, where the
conditional-return pattern is safe). Re-validated clean after the fix
(section 16).
