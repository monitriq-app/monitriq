STATUS

METHOD (what "browser" means here)
No browser-automation tool was available in the session, so QA used the
installed Google Chrome (headless) driven by playwright-core installed in a
scratchpad directory OUTSIDE the repo (no repo dependency change). The
user's own dev server (port 3000, pointed at the remote project) was left
running and untouched. QA ran against a scratch COPY of the repo built with
env overrides pointing at the LOCAL Supabase stack (127.0.0.1:54321) — the
remote Monatriq Dev project was never contacted. For authenticated screens
a throwaway LOCAL auth user was created (admin API, local only), onboarded
through the real UI (profile name/currency/timezone only) and deleted at
the end. No financial data was seeded; app screens were inspected in their
real empty states. Screenshots live in the scratchpad (not committed).

DEFECTS FOUND
1. (Proven, fixed) Header mark distorted. HeaderBrand rendered the mark in
   a square 20x20 box (`h-5 w-5`) while the supplied mark is 699x545
   (aspect 1.28) with default object-fit: fill — the artwork was squeezed
   horizontally in the app shell on every authenticated page and theme
   (measured: natural 699x545, rendered 20x20). Visible in the crop as a
   narrow M. Fix (CSS only): mark now `h-6 w-6 object-contain`, and
   BrandLogo's mark variant adds `object-contain` itself so no caller can
   distort the artwork. Re-verified: rendered 24x24 box, fit=contain,
   proportions correct in dark and light.
2. (Sizing, fixed) Wordmark too small relative to surrounding UI. The
   supplied horizontal logo at the old `h-7`/`h-8` classes gave a
   ~100px-wide lockup whose wordmark was visibly smaller than the typed-text
   lockup it replaced and small next to the 24px "Sign in" heading. Fix
   (CSS only): auth layout `h-7` -> `h-9`, landing `h-8` -> `h-10`. Re-verified
   no layout shift, no overflow.
3. (Observed, NOT logo-related, not fixed) At 768px every authenticated
   page overflows horizontally by 2px: the header's right-hand 48px account
   button ends at x=770 in a 768px viewport (header content is wider than
   the viewport at the md breakpoint). The brand mark box is fixed-width and
   "Monitriq" is not wider than "Monatriq", so the rebrand is not the cause;
   this is pre-existing header-cluster crowding at the tablet breakpoint.
   Out of scope for this phase (no unrelated redesign). Logged as a
   follow-up.
Stale text missed by S1B: none found.
