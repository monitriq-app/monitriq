P0-E3-S1E — LIVE AUTH PASSWORD TOGGLE VERIFICATION & FIX
================================================================

STATUS
COMPLETE. The eye / eye-off control is visibly rendered inside the password
field on the REAL running app (the user's own dev server, port 3000, from
the current repo), in dark and light themes, and was verified with real
browser screenshots. Nothing committed or pushed.

ROOT CAUSE
The S1D report was correct that the feature was implemented, but its QA was
done on a scratch copy and looked only at DOM/structure and a dark-theme
screenshot. Verified on the real server this phase:
- components/ui/PasswordInput.tsx exists, and app/(auth)/login, signup and
  update-password all import and render it (grep-confirmed).
- The live :3000 HTML contained the button (type="button",
  aria-label="Show password", aria-pressed=false, svg icon) and the input
  with pr-12. So the control was rendered — not missing, not stale.
- It was effectively INVISIBLE because of low contrast and small size: the
  icon used the muted text token (text-text-muted) at 18px. Measured on the
  real page: dark theme rgb(112,123,130) on rgb(11,23,42) (~4:1, faint);
  light theme rgb(162,167,174) on a near-white field (~2.3:1 — barely
  perceptible). The earlier "before" screenshot confirms a faint grey outline
  icon. No clipping, overflow-hidden, z-index, or position problem existed:
  the 48x48 button sat at the field's right edge, vertically centered.

FIX (single file)
components/ui/PasswordInput.tsx only:
- icon color text-text-muted -> text-text-secondary (hover: text-text-primary)
  => dark rgb(216,222,228) on rgb(11,23,42) ~13:1; light ~rgb(104,111,123) on
  near-white ~5:1;
- icon size 18 -> 20 with strokeWidth 2 (Eye / EyeOff, existing lucide);
- added z-10 and cursor-pointer to the button.
Layout unchanged and already correct: wrapper `relative`, input `pr-12`,
button `absolute inset-y-0 right-0 w-12` (48px target), icon centered =>
14px right inset. The shared Input component was not modified.

LESSON / RISK
Structural DOM checks are not enough to prove a control is perceivable;
contrast must be measured on the real page in both themes. The muted text
token is too faint for small interactive icons on the light theme —
other places that use text-text-muted for interactive icons may have the
same issue (not audited here).
