CreateGoalSheet (bottom sheet; "New Goal"/"Create Goal"; Quick Add > Goal now opens /goals?new=1 with the sheet open). 10. GOAL DETAIL
GoalDetailSheet (tap a card): headline, progress, facts, target date, Required pace, protection, Set Money Aside, and "Manage this goal".

11. GOAL FUNDING / ALLOCATION
User-facing wording is "Set Money Aside" (not "Add Money"): the canonical operation marks cash already in one of the user's own accounts for a goal and moves/spends nothing; the sheet says so. Only the user's same-currency, non-archived accounts are offered. Verified: allocating changes goal totals, not cash balances.

12. GOAL ADVANCED CONTROLS
Inside Manage: protect toggle, change target amount/date (append-only recordGoalTarget), and "Release or move money" (release / move to another same-currency goal, canonical functions) — shown only when money is set aside. 14. DEBTS UI
"Debts" / "What you owe." Total owed per currency (canonical native totals, never combined), debt cards (name, type, interest only if entered, still owed, final payment date only if entered), More details (owed to, paid back so far, started), Record Payment sheet (paid from same-currency account; toward the debt / interest / fees).

AddDebtSheet: Name, Type of debt, Currency, "Starting amount owed" (states it does not add money), and More details: "Who do you owe?", interest %, final payment date. Uses createLiability unchanged. Empty state: "No debts tracked yet." + the requested body copy + Add Debt.

18. MONEY OWED UI
"Money Owed to You" / "Track money you expect to receive." Per-currency "Still to be paid" totals with the note "Money owed to you is not cash you can spend until it is paid." Cards: name, expected date, still owed, paid back so far, estimate (labelled an estimate), last follow-up, settled state, More details ("Amount owed in total" instead of "Face amount"). Empty: "No money owed to you is being tracked."

1. SECONDARY PAGE NAVIGATION
Problem: /liabilities and /receivables (secondary routes, deliberately not in the primary nav) had no in-app way back.
Fix: one shared component, components/layout/BackLink.tsx, placed at the top of Debts, Money Owed to You and Rules (Rules had the same problem). It is a labelled button ("Back to previous screen"), 48px high, with the global visible focus ring. If the visitor arrived from another page of this site (same-origin referrer and history), it calls router.back(); otherwise it goes to Home, so a page opened directly (new tab, bookmark) never dead-ends. The app shell, header, branding and bottom/desktop navigation are unchanged, and these pages were not added to primary navigation.
Verified in headless Chrome (dark and light): Goals -> Debts -> Back returns to Goals; Money -> Money Owed -> Back returns to Money; Assets -> Rules -> Back returns to Assets; a directly opened /liabilities goes Back to Home. Control height 48px on all three pages; focus outline visible; no horizontal overflow at 320, 360, 393, 430 and 768 px on Debts, Money Owed, Rules and Goals.
Observation, not changed: Financial Position (also an account-menu route) has the same missing-Back situation; it was outside the requested scope and can reuse BackLink in one line.

2. GOALS PROTECTED SUMMARY
Problem: with a protected goal and nothing set aside, both tiles showed a zero amount ("NGN 0" twice).
Fix (presentation only, lib/domain/goals/presentation.ts and the tile in GoalsWorkspace): the Protected tile now lists per-currency protected amounts only where money genuinely exists; when protected goals exist but no protected money is set aside it shows the goal count plus "No money set aside". Currencies are still never combined. Verified in the browser: zero state reads "PROTECTED | 1 goal | No money set aside"; after setting aside NGN 100,000 it reads "PROTECTED | 1 goal | NGN 100,000". The Set Aside tile is unchanged.
